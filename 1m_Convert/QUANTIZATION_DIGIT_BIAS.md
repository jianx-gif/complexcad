# 量化数值分布偏置分析（供与导师讨论）

> 针对 koor 量化（固定 scale=100 把毫米尺寸映射到 [1,10000] 整数网格）在
> **逐位 token 生成模型（CAD-Recode 类）** 下的数值分布问题。
> 测量样本：test split 转换成功的 8794 个模型，共 **249,656** 个数值字面量。

## 1. 问题陈述

CAD-Recode 把 CadQuery 代码当作文本，**逐字符（逐位数字）token** 生成。
因此每个数值的「个位、十位…」分别是独立的预测 token。若某些低位 token
在训练标签里几乎不出现，网络就学不到、也生成不出它们。

## 2. 实测分布（核心证据）

| 指标 | 数值 |
|---|---|
| 数值字面量总数 | 249,656 |
| 100 的整数倍（非 0） | 85,429（**34.2%**）|
| **末位（个位）= 0** | 146,996（**59.7%**）|
| 末位 = 1 | 11.1% |
| 末位 = 2 | 21.9% |
| 末位 = 3 / 5 / 7 / 8 / 9 | 各约 **0.7%–1.0%** |

## 3. 根因

1. **原始尺寸是「人类友好」的整毫米**：设计师爱用 5、8、10、20、30 这类值，
   小数极少。原始数据本身末位就偏 0/5。
2. **固定 ×100 把这种偏置放大并锁死到低两位**：`8.0 → 800`、`30.0 → 3000`，
   个位、十位**恒为 0**。末位 1/2 的 11%/22% 主要来自 `translate` 平移量
   （offs，落在 1、2 这种小整数）和未缩放的角度/比例，不是真实尺寸。
3. 结果：个位 token 的标签里 60% 是 `0`，3/5/7/9 各仅 ~1%。网络强烈倾向
   输出末位 0，**对非整百尺寸（真实带小数的零件）泛化差** —— 这与任务书
   「avoid quantization truncation, guarantee parameter value accuracy」相悖。

> 注：scale 分布显示 8198/8794（93%）件 scale=100，其余是大件的自适应
> 非整 scale。所以问题主要由 scale=100 这一大类贡献。

## 4. 可选修法与取舍

### 方案 A：随机/多尺度 scale（打破低位锁死）
对每个模型从一组 scale 里随机取（如 {50, 80, 100, 125, 160, 200}），
或在保证落盒前提下随机抖动。`8.0 × 125 = 1000`、`8.0 × 160 = 1280`——
个位/十位被填充，各位 token 都获得样本。
- ✅ 直接解决低位 token 饥饿；数据增广，提升数值鲁棒性
- ✅ 还原仍精确（每件存自己的 scale）
- ❌ 需重跑整个转换；同一零件不同 scale 下代码不同，需确认下游可接受
- ❌ scale 本身也成了要预测/已知的量，要想清楚它怎么提供给模型

### 方案 B：更细网格 + 不强制整百（如 scale=1000 或保留小数位）
提高分辨率让真实尺寸的小数位进入低位 token。
- ✅ 保留更多精度信息
- ❌ 原始仍是整毫米，×1000 只是把 0 推到更低位，**治标不治本**
- ❌ 坐标更大，OCCT 执行更慢

### 方案 C：保持 ×100，下游做数值数据增广
数据集不动，训练时对尺寸做随机缩放/抖动增广。
- ✅ 数据集核心设计不变，风险最低
- ✅ 把问题交给训练 pipeline，更灵活
- ❌ 不属于数据集职责；需下游配合
- ❌ 增广后还要保证几何合法（缩放可能破坏装配关系）

### 方案 D：保持现状，明确记录此特性
若下游用连续标量回归（非逐位 token），末位偏 0 不构成问题。
- ✅ 零改动
- ❌ 仅当架构改变时成立；当前基线 CAD-Recode 是逐位 token，不适用

## 5. 建议讨论点（带给导师）

1. 下游确认用 **逐位 token**（CAD-Recode）→ 则方案 A 最对症。
2. 若担心「同一零件多 scale」破坏配对唯一性，可折中：**固定但按零件
   尺寸分桶选 scale**（小件 ×200、中件 ×100、大件 ×50），既填充低位
   又保持每件 scale 确定。
3. 任务书强调「建模精度」——随机 scale 的增广恰好能论证「数据集对数值
   精度鲁棒」，是论文的一个加分论点。
